# English Lexicon Trainer — карта проекта

> Личное приложение для закрепления английской лексики **в контексте** (уровень C1/C2).
> Дата планирования: 2026-08-27. Обновлено: 2026-08-28.

---

## 1. Зачем

Существующие инструменты остаются, но не закрывают тренировку лексики в контексте:

| Инструмент | Роль | Статус |
|---|---|---|
| Elevate | узнавание новых слов из упражнений | остаётся, не заменяется |
| Multitran | ручной справочник переводов | остаётся |
| Me Words | карточки, но только изолированные слова | **заменяется этим приложением** |

**Нужно:** своё приложение для закрепления и тренировки лексики в контексте.

**Ключевое ограничение UX:** упражнения только **тап-ориентированные**, без набора текста
(сценарий — вечером, уставшей, в кровати, с телефона). Проверка ответа — простое
сравнение с эталоном, без NLP.

## 2. Пользовательские флоу

### 2.1. Добавление слова

```
ввод англ. слова / фразы
   → (опц.) запрос к MyMemory API за вариантами RU-перевода
   → показ вариантов перевода + поля для ручного ввода
   → пользователь отмечает ОДИН ИЛИ НЕСКОЛЬКО вариантов и/или дописывает свои вручную
   → сохранение: одно слово = 1..N значений (word_senses)
   → раскладка по папкам (папки создаёт пользователь)
```

- **Основной путь — ручной ввод.** Словарное API — только ускоритель, не критичная
  зависимость.
- **RU-перевод:** MyMemory API (без ключа, без карты) — подсказывает варианты глоссы.
  Часть речи / транскрипцию / определение / пример на этом этапе **не тянем** — эти
  поля либо руками, либо позже кнопкой обогащения (см. ниже).
- Одно англ. слово может иметь **несколько переводов/значений**, каждое — отдельная
  тренируемая единица.
- Слово можно позже дополнять новыми значениями.
- **Фразовые выражения / коллокации:** сразу ручной ввод значения, без ощущения ошибки.
- **Фоллбек:** API недоступен / лимит исчерпан → мгновенный переход на ручной ввод.
- **Кэш:** каждый ответ MyMemory сохраняем у себя, одно слово не запрашиваем дважды.
- **Обогащение через OpenRouter (опционально, позже):** кнопка «дополнить через ИИ» —
  батч-запрос (несколько слов = 1 запрос) на часть речи / определение / пример /
  нюанс значения под уже выбранный смысл. Не автоматически — чтобы не жечь квоту.
- **Миграция из Me Words не делается** — словарь набирается заново, с нуля.

### 2.2. Формирование набора для тренировки

- **Вручную:** выбрать папку + указать лимит количества слов.
- **Автоматически:** «самые невыученные» из конкретной папки или отовсюду — по прогрессу.

### 2.3. Тренировка

```
набор значений → генерация набора упражнений одним запросом к OpenRouter (:free)
   → прохождение упражнений тапами
   → (опц.) «подсмотреть перевод» внутри упражнения → слово засчитывается нейтрально
   → сравнение с эталоном
   → экран разбора: переводы / транскрипция / примеры по всем задействованным значениям
   → запись попыток, обновление прогресса каждого значения
```

## 3. Модель прогресса (мини-SRS)

Прогресс хранится **на уровне значения** (`word_sense`), не слова — для C1/C2 важно
различать оттенки: выученное частотное значение не должно маскировать невыученное редкое.
«Невыученность» слова = агрегат по его значениям.

Хранить по каждому значению:
- счётчик правильных ответов
- счётчик неправильных ответов
- дата последней тренировки

Счётчики — денормализация; источник истины — таблица `attempts`, чтобы формулу
приоритизации можно было менять и пересчитывать задним числом.

### Стартовая формула приоритизации

```
accuracy  = correct / (correct + incorrect + 1)
recency   = min(days_since_last_trained / 14, 1)        # 0..1
priority  = 0.6 * (1 - accuracy) + 0.4 * recency
новые значения без попыток → priority = 0.9
```

Подбор набора: сортировка по `priority desc`, срез по лимиту.

**Смешивание новых и повторяемых значений (только автоподбор):** ограничивать долю
новых значений в наборе (ориентир ~40%, настраивается), иначе свежедобавленные слова
(`priority = 0.9`) вытесняют повторение. В ручном режиме (папка + лимит) ограничения
нет — набор формирует пользователь. На добавление слов в словарь ограничений нет вообще.

Формула — черновая, подлежит настройке на реальных данных.

## 4. Виды упражнений (5 типов, список расширяемый)

| # | Тип | Тренирует | Проверка |
|---|---|---|---|
| 1 | Текст с кликабельными словами | узнавание + значение | тап по целевому слову → выбор перевода из вариантов |
| 2 | Пропуски + банк слов | подстановка по смыслу | тап по кнопке-слову (нужное + отвлекающие похожей формы/значения) |
| 3 | Multiple choice в контексте | узнавание англ. слова в контексте | выбор 1 из 3–4 англ. слов |
| 4 | Сортировка тапом по группам | оттенки значения / регистр речи (C1/C2) | разложить слова по 2–3 смысловым группам |
| 5 | Верно/неверно | корректность употребления по смыслу | бинарный выбор |

**Убрано из первоначального списка:** «собери слово по частям», «тап по неверно
использованному слову». Тренировки написания в приложении нет — это осознанно,
согласуется с tap-only.

**Отклонено:** свободный ввод английского предложения — сложная проверка + нежелание печатать.

### Упражнения без LLM (базовый режим)

Отдельная категория — строятся прямо из `word_senses`, без запроса к ИИ:

- сопоставление пар EN↔RU тапами;
- флеш-карточка с самооценкой («знал / не знал») — чистый SRS;
- выбор перевода из вариантов (дистракторы — из соседних значений / папок пользователя).

Назначение: рабочий режим при исчерпанной квоте OpenRouter, офлайн и при недоступности
словарного API; дешёвая ежедневная практика. Контекст они не тренируют — чередовать
с контекстными (LLM) упражнениями.

### Формат генерации

- LLM возвращает **строгий JSON по схеме на каждый тип упражнения**, а не «текст».
  Пример: `{ text, blanks[], options[], correct[], distractors_meta }`.
- В payload каждого упражнения есть секция `glossary` — по всем задействованным
  значениям: слово, перевод, транскрипция, часть речи. Из неё фронт строит
  «подсмотреть перевод» и экран разбора **без обращения к ИИ**.
- Фронт только рендерит и сравнивает ответ с `correct`.
- **Отвлекающие варианты (distractors)** для типов 2, 3, 4 — часть JSON-выдачи LLM;
  опционально подмешивать реальные слова из соседних папок пользователя.
- **Валидация после генерации:** все целевые слова реально присутствуют в тексте,
  число пропусков/вариантов сходится со схемой. Иначе — регенерация или фоллбек-модель.
- Тексты просить писать на уровне C1/C2.

### Подсказка «подсмотреть перевод»

В любом упражнении можно открыть перевод целевого слова (кнопка под вопросом).
Слово тогда засчитывается **нейтрально**: не верно и не неверно, счётчики прогресса
не меняются, факт фиксируется в `attempts.hint_used`. Точное поведение уточняется
отдельно по каждому типу упражнения — нейтральный зачёт это базовое правило.

### Экран разбора после упражнения

После ответа — сводка по всем задействованным значениям: слово, перевод,
транскрипция, пример, `definition_en` при наличии, верно/неверно. Данные берутся
из `glossary` в payload, запрос к ИИ не нужен.

## 5. Хранение упражнений (экономия места и квоты)

- Одним запросом к LLM генерируется **сразу несколько упражнений**.
- Держать **небольшой запас** сгенерированных упражнений (например 3–5) на случай,
  если запрос к ИИ упадёт или дневная квота исчерпана.
- **Пройденные без ошибок упражнения не храним** вообще.
- Упражнения с ошибками — опционально можно придержать для повторного показа (решить позже).
- Цель: не копить большой архив упражнений в БД.

---

## 6. Экономия квоты OpenRouter (50 запросов/день)

- Одна генерация = целый набор упражнений на сессию (батч), а не запрос на упражнение.
- Фоновая пред-генерация запаса, когда квота есть.
- **Счётчик квоты — на сервере** (таблица `quota_usage`: дата + count), сброс по
  UTC-полуночи как у OpenRouter. Клиентский счётчик врёт между устройствами и после
  офлайна. В UI показываем «осталось запросов сегодня» из серверного значения.
- Рядом — мини-лог генераций (`generation_log`: модель, ок/ошибка, тип ошибки),
  чтобы видеть, какие `:free`-модели реально отдают валидный JSON.
- Квота исчерпана → отдаём упражнения из запаса, затем переключаемся на упражнения без LLM.

## 7. Технологический стек

```
┌───────────────────────────────────────────────────────────────┐
│  Frontend: Vue  →  Cloudflare Pages (поддомен имеющегося домена) │
└───────────────┬───────────────────────────────────────────────┘
                │
┌───────────────▼───────────────────────────────────────────────┐
│  Backend: Cloudflare Workers (free tier, интеграция с Pages     │
│  без доп. настройки; отдельный VPS НЕ арендуется)               │
└───┬───────────────┬───────────────────┬───────────────────────┘
    │               │                   │
┌───▼─────┐  ┌──────▼────────┐  ┌───────▼────────────┐
│  Neon    │  │  MyMemory     │  │  OpenRouter        │
│ Postgres │  │  API          │  │  (:free модели)    │
│ (free)   │  │ RU-перевод    │  │  генерация упр.    │
└──────────┘  │ (без ключа)   │  └────────────────────┘
              └───────────────┘
```

### Frontend
- Vue, деплой на Cloudflare Pages, поддомен уже имеющегося домена (DNS на Cloudflare).

### Backend
- Cloudflare Workers, бесплатный тариф. Отдельный VPS не заводится.

### База данных
- **Neon** (serverless Postgres, free). Референс подхода: `budget-jar/DOCS.md`,
  `budget-jar/MIGRATION_PLAN.md` (не обязательно повторять 1:1).
- Объём данных маленький — влезает в free-лимит. Отдельный проект в том же аккаунте.
- **Драйвер:** Cloudflare Workers не открывают сырой TCP → обычный `pg` не работает.
  Использовать `@neondatabase/serverless` (HTTP/WebSocket).
- Free-проект Neon засыпает при простое: первый запрос после паузы ~0.5с холодный —
  заложить состояние загрузки в UI (скелетоны, а не пустой экран).

### AI API — генерация упражнений
- **OpenRouter**, бесплатные модели (`:free`).
- Лимиты: 20 req/min всегда; 50 req/day без пополнения (решено — хватает);
  1000/day после разового пополнения от $10 (на будущее, не сейчас).
- **Модель не хардкодить:** перебор нескольких `:free` моделей с фоллбеком
  либо алиас `openrouter/free` (авто-роутер).

### Перевод слов — без ИИ
- **MyMemory API** (`api.mymemory.translated.net`) — translation memory + MT.
  Отдаёт варианты RU-перевода слова/фразы. **Без регистрации, без ключа, без карты.**
  Лимит: ~5000 слов/день анонимно, ~50000 с параметром `de=<email>` (email без
  верификации, просто идентификатор лимита).
- Даёт только перевод — части речи / транскрипции / структурированных значений нет.
- Из Worker вызывается server-side; в secrets ничего не кладём (константный URL +
  опционально email в конфиге).
- **Кэшируем** каждый ответ в своей БД — повторно одно слово не запрашиваем.
- **Отклонено:** Yandex Dictionary API — сложная регистрация через Яндекс Облако,
  вероятная привязка карты.
- **Возможные будущие источники (не сейчас):**
  - Free Dictionary API (dictionaryapi.dev, без ключа) — IPA, часть речи,
    EN-определения, примеры. Данные не привязаны к выбранному значению.
  - Обогащение через OpenRouter — часть речи / определение / пример / нюанс под
    выбранный смысл, батч-запросом, по кнопке.
  - Офлайн-словарь из дампа Wiktionary (kaikki.org / Wiktextract) в таблицу —
    ноль внешних зависимостей, работает офлайн.

### Аутентификация и пользователи
- **Через Telegram** (Telegram Login Widget / бот) — привычный вариант (было в двух
  прошлых проектах). Отдельный бот под приложение — чтобы задать домен через BotFather.
- **Таблица `users`** (telegram_id, name). Доступ контролируемый: первый вошедший
  становится владельцем; остальные пускаются, только если владелец завёл им строку
  в `users` (SQL или мелкий admin-экран позже). Не в env.
- **Данные у каждого пользователя свои** (мультиарендность): `folders`, `words` и
  вся цепочка привязаны к `user_id`; каждый запрос API фильтруется по текущему
  пользователю. Сессия несёт внутренний `user_id`.
- **Общее между пользователями:** `translation_cache` (переводы не персональные) и
  квота OpenRouter — ключ один на приложение, счётчик `quota_usage` глобальный.
  Пока владелец + 1–2 человека это приемлемо; при росте — вводить дневной лимит на
  пользователя.

### Несколько устройств
- Нужно: заход с телефона и с ноутбука. В онлайне работает без доп. усилий —
  источник истины на сервере (прогресс, квота, набор), оба устройства ходят в один API.
- **Идемпотентность записи попыток:** клиент генерит UUID (`client_id`) на каждую
  попытку, сервер дедупает по нему; счётчики в `word_sense_progress` пересчитываются
  из `attempts`, а не инкрементятся вслепую — защита от ретраев и параллельных
  устройств. Дёшево, делаем сразу.

### Офлайн-прохождение — НЕ в MVP
- Желательно, но не приоритет. Отдельный поздний этап.
- Идея: пред-загрузка набора на день в браузер (IndexedDB), прохождение офлайн,
  батч-синк при появлении сети (дедуп по тому же `client_id`).

### PWA для iPhone
- Желательно, **не в MVP** — отдельный этап после веб-версии.

## 8. Черновая схема БД

| Таблица | Поля (черновик) |
|---|---|
| `users` | id, telegram_id (uniq), name, is_owner, created_at |
| `folders` | id, user_id, name, created_at |
| `words` | id, user_id, text (англ.), transcription?, is_phrase, source (`api`/`manual`), created_at, deleted_at?; уникальность по (`user_id`, нормализованный `text`) |
| `word_folders` | word_id, folder_id (M:N — одно слово в нескольких темах; оба принадлежат одному user) |
| `word_senses` | id, word_id, translation, part_of_speech?, definition_en?, example?, source (`api`/`manual`), position, deleted_at? |
| `word_sense_progress` | word_sense_id, correct_count, incorrect_count, last_trained_at |
| `attempts` | id, user_id, client_id (UUID, дедуп синка), word_sense_id, exercise_id?, exercise_type, is_correct (nullable — `null` при подсказке), hint_used, answered_at |
| `exercises` | id, user_id, type, payload (JSON по схеме, включая `glossary`), target_sense_ids, status (`reserve`/`in_use`), created_at |
| `translation_cache` | query (PK), response_json, fetched_at — **общая**, не привязана к user |
| `quota_usage` | date (PK), count — **общая** (один ключ OpenRouter на приложение) |
| `generation_log` | id, model, ok, error_kind?, created_at |

Точная схема — подлежит детальной проработке.

| 7. После MVP | офлайн-прохождение (кэш набора + синк), озвучка слов (TTS браузера), отмена последнего ответа, возобновление прерванной сессии |
