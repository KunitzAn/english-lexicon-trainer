## Этап 5.1. Выученность слов: модель + настройки + отображение

Обсуждено, зафиксировано. Реализуем после этапа 5. Модель выученности —
**в процентах (0–100 %)**, без уровней, **настраиваемая из интерфейса**.
Отдельного экрана «выученность» нет — процент живёт в списках слов; агрегатная
картина уходит в экран «Прогресс» (его v2).

### A. Модель выученности (на значение)

Считается **из `attempts`** для каждого значения (хронологический проход по дням
с активностью) + пользовательские настройки. Значение слова с несколькими
значениями в списке = **минимум по значениям** (слово не «полное», пока слабо
хоть одно; добавили новое значение к выученному слову → полоса слова падает).

Алгоритм на значение (`m` ∈ [0, 100], старт 0):

```
для каждого дня D с ответами (по возрастанию):
  если был предыдущий активный день:
    m -= затухание за простой (D − prev_day) с учётом grace и того, learned ли сейчас
    m = max(m, 0)
  correct_seen_today = 0
  для каждого ответа дня D (по возрастанию):
    верно →
      g = correct_seen_today == 0 ? (D — новый день ? gain_new_day : gain_same_day)
        : correct_seen_today == 1 ? gain_same_day
        : gain_repeat_more
      m += g;  correct_seen_today += 1
    неверно → m -= penalty_wrong
    подсказка → без изменений
  m = clamp(m, 0, 100)
  prev_day = D
# хвостовое затухание до сегодня
m -= затухание за (сегодня − prev_day);  m = clamp(m, 0, 100)
```

`learned` на любой момент = `m >= learned_threshold` (не «липкий»: неверные
ответы могут увести обратно ниже порога — тогда затухание снова включается,
если оно «только пока не выучено»).

Дни режем по локальной полуночи пользователя (как серию на «Прогрессе» —
`tz_offset` с клиента).

### B. Настройки выученности (редактируются из UI)

Хранение: `users.settings jsonb` (или таблица `user_settings`). Экран/шит
«Что считать выученным»: точка входа — шестерёнка на «Прогрессе». Кнопки
«сбросить к средним» и «пересчитать» (полный пересчёт из `attempts` после
смены gain-параметров). **В UI всё в процентах**, не в днях.

| ключ | смысл | дефолт |
|---|---|---|
| `gain_new_day` | +% за верный ответ в **новый** день | 20 |
| `gain_same_day` | +% за **1-й повторный** верный ответ в тот же день | 5 |
| `gain_repeat_more` | +% за **2-й и последующие** повторные в тот же день | 2 *(открыто)* |
| `penalty_wrong` | −% за неверный ответ | 15 |
| `learned_threshold` | с какого % слово «выучено» (метки, «тема пройдена») | 100 |
| `decay_enabled` | включено ли забывание (полоса тает без тренировки) | true |
| `decay_per_day` | −% за день простоя (пока не выучено) | 5 |
| `decay_after_learned` | тает ли после достижения выученности | false |
| `decay_per_day_learned` | −% за день простоя после выучено (если флаг вкл) | 0 |
| `decay_grace_days` | сколько дней простоя не тают | 3 *(открыто: оставить/убрать)* |

Затухание: `idle = сегодня − последний_активный_день`; если
`idle > decay_grace_days` и затухание применимо →
`m -= rate * (idle − decay_grace_days)`, `rate` = `decay_per_day` или
`decay_per_day_learned`. «Применимо» = `decay_enabled` И (`decay_after_learned`
ИЛИ `m < learned_threshold`).

Дефолты по умолчанию: **выученное слово не тает** (`decay_after_learned = false`,
`decay_per_day_learned = 0`). При таком темпе 20 % / новый день → ~5 чистых
дней до 100 %; можно показать это read-only подсказкой (открытый вопрос).

### C. Отображение
