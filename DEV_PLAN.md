# English Lexicon Trainer — пошаговый план разработки

> Рабочий план сборки. Основан на `PLAN.md`, но упорядочен под реализацию.
> Дата: 2026-08-28.
>
> **Принцип:** вертикальные срезы, деплой с первого этапа, приложение должно быть
> «проходимо руками с телефона» как можно раньше.

## Как пользоваться

- Этапы идут по порядку, внутри этапа — чек-лист.
- «Готово когда» — критерий закрытия этапа.
- Не начинать следующий этап, пока текущий не задеплоен и не проверен вручную на телефоне.

## Отличие порядка от `PLAN.md` §10

В `PLAN.md`: генерация (этап 3) → упражнения (этап 4).
Здесь наоборот: сначала **упражнения без LLM** (этап 3) — чтобы получить работающий
тренажёр без зависимости от надёжности JSON от OpenRouter, — потом слой генерации (этап 4).

## Этап 0. Инфраструктура и каркас

**Решения, которые фиксируем здесь:**

- [ ] Структура репозитория: моно — `/web` (Vue), `/worker` (API), `/db` (схема + миграции).
- [ ] ORM / миграции: **Drizzle + drizzle-kit** (совместим с `@neondatabase/serverless`,
      типизированные запросы) — или голый SQL + раннер. Выбрать.
- [ ] Формат API: Pages Functions vs отдельный Worker с service binding. Выбрать.
- [ ] Секреты Worker: `DATABASE_URL`, `OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`,
      `SESSION_SECRET`, `ALLOWED_TELEGRAM_IDS`, `MYMEMORY_EMAIL` (опц.).

**Задачи:**

- [ ] Репозиторий, базовый Vue (Vite), базовый Worker.
- [ ] Neon: отдельный проект, `DATABASE_URL` (pooled), подключить `@neondatabase/serverless`
      из Worker, проверить `select 1`.
- [ ] Cloudflare: Pages для `/web`, Worker для API, поддомен + DNS, CORS Pages↔Worker.
- [ ] OpenRouter: аккаунт, ключ, тестовый запрос к `:free` модели из Worker.
- [ ] Telegram: бот через BotFather, `/setdomain` на поддомен.
- [ ] CI: линт + сборка на пуш (GitHub Actions).
- [ ] `.env.example`, README с командами запуска.

**Готово когда:** пустой Vue задеплоен на поддомен, `/api/health` отвечает и ходит в Neon.

## Этап 1. Аутентификация (Telegram)

Решено: Telegram (как в двух прошлых проектах). Нужен **отдельный бот** под приложение,
чтобы задать домен через BotFather. Telegram Premium уже есть.
_(Cloudflare Access с входом по одноразовому коду на почту не требует Google-консоли
и карты — но остаёмся на Telegram по привычке и совместимости с прошлыми проектами.)_

- [ ] Telegram Login Widget на фронте.
- [ ] Worker: проверка подписи — HMAC-SHA256 от bot token, проверка свежести `auth_date`.
- [ ] Сверка `id` пользователя с `ALLOWED_TELEGRAM_IDS`.
- [ ] Сессия: httpOnly + Secure + SameSite cookie с подписанным JWT (HS256,
      `SESSION_SECRET`), срок 30–90 дней.
- [ ] Middleware: все `/api/*` кроме `/health` и `/auth/*` требуют валидную сессию.
- [ ] Фронт: guard роутов, экран «войти».

**Готово когда:** без входа API отдаёт 401, после входа — 200; чужой Telegram ID не пускает.

## Этап 2. Ядро данных: папки, слова, значения

**Схема:**

- [ ] `folders(id, name, created_at)`
- [ ] `words(id, text, transcription?, is_phrase, source, created_at, deleted_at?)`
      + уникальный индекс по нормализованному `text` (глобально, слово — одна сущность).
- [ ] `word_folders(word_id, folder_id, PRIMARY KEY (word_id, folder_id))` —
      M:N, одно слово может быть в нескольких темах.
- [ ] `word_senses(id, word_id, translation, part_of_speech?, definition_en?, example?,
      source, position, created_at, deleted_at?)`
- [ ] `word_sense_progress(word_sense_id PK, correct_count, incorrect_count, last_trained_at)`
- [ ] `translation_cache(query PK, response_json, fetched_at)`
- [ ] Первая миграция, применить к Neon.

**API:**

- [ ] CRUD папок.
- [ ] `POST /api/words` — text, `folder_ids[]` (одна или несколько тем), массив
      выбранных/введённых значений.
- [ ] `GET /api/words/lookup?q=` — прокси MyMemory (`langpair=en|ru`, `de=` из конфига),
      нормализация ответа в список вариантов, запись в `translation_cache`.
      Недоступен / лимит → пустой список, фронт уходит в ручной ввод.
- [ ] Дедуп: добавление существующего слова → предложить дописать значение и/или
      добавить в ещё одну тему.
- [ ] Нормализация `text`: trim, lower, схлопывание пробелов.
- [ ] Добавление/удаление слова из темы (правка `word_folders`).
- [ ] Правка / удаление (soft delete) слова и значения.
- [ ] Дописывание новых значений к существующему слову.

**Фронт:**

- [ ] Список папок, содержимое папки.
- [ ] Экран добавления слова: ввод → варианты MyMemory чекбоксами + поля ручного ввода
      → выбор одной или нескольких тем → сохранить.
- [ ] Экран слова: значения, темы, прогресс, кнопки правки.

**Готово когда:** с телефона можно создать тему, добавить слово с 2+ значениями
(через подсказку и руками) сразу в несколько тем, увидеть его в каждой.

## Этап 3. Прогресс + подбор набора + упражнения без LLM

Здесь приложение впервые становится тренажёром — целиком без внешних API.

**Прогресс:**

- [ ] `attempts(id, client_id UNIQUE, word_sense_id, exercise_id?, exercise_type,
      is_correct nullable, hint_used, answered_at)`
- [ ] Запись попытки: пересчёт `word_sense_progress` из `attempts` (не инкремент).
- [ ] Функция приоритета (формула `PLAN.md` §3), новые значения → `priority = 0.9`.

**Подбор набора:**

- [ ] Ручной: папка + лимит.
- [ ] Авто: топ по `priority`; в авто-режиме доля новых значений ≤ ~40% (в конфиг).
- [ ] `GET /api/training-set?mode=&folder=&limit=`

**Упражнения без LLM** (из `word_senses`, без внешних запросов):

- [ ] Тип A: сопоставление пар EN↔RU тапами.
- [ ] Тип B: флеш-карточка с самооценкой «знал / не знал».
- [ ] Тип C: выбор перевода из вариантов (дистракторы — из соседних значений / папок).
- [ ] Раннер сессии: упражнение → тап-ответ → сравнение с эталоном → запись `attempt` → далее.
- [ ] «Подсмотреть перевод» → `hint_used=true`, `is_correct=null`, счётчики не трогаются.
- [ ] Экран разбора после упражнения / в конце сессии.
- [ ] Итог сессии: верно / неверно, обновлённый прогресс.

**Готово когда:** полный цикл «собрать набор → пройти сессию тапами → прогресс изменился»
работает без OpenRouter и без сети к словарю.

## Этап 4. Генерация контекстных упражнений (OpenRouter)

- [ ] JSON-схема на каждый тип (1–5 из `PLAN.md` §4) + секция `glossary`.
- [ ] Промпты (C1/C2, строгий JSON; `response_format`/`json_schema` где модель
      поддерживает, иначе `json_object`).
- [ ] Клиент OpenRouter: цепочка `:free` моделей с фоллбеком, таймаут, ретрай с
      бэкоффом в пределах 20 req/min.
- [ ] Батч: один запрос = набор упражнений на сессию.
- [ ] Валидатор ответа: целевые слова есть в тексте нужное число раз, кол-во
      пропусков / вариантов сходится со схемой, `correct` ⊆ допустимых,
      дистракторы ≠ правильному. Провал → регенерация / фоллбек-модель /
      фоллбек на упражнение без LLM.
- [ ] `exercises(id, type, payload jsonb, target_sense_ids, status reserve|in_use, created_at)`
- [ ] Запас 3–5 упражнений; фоновая пред-генерация при наличии квоты.
- [ ] `quota_usage(date PK, count)` — серверный счётчик, сброс по UTC.
      `generation_log(id, model, ok, error_kind?, created_at)`.
- [ ] Пройденные без ошибок упражнения — удаляем (или cooldown-пул — решить, `PLAN.md` §9.5).
- [ ] Фронт: типы 1–3, затем 4–5.
- [ ] Раннер чередует упражнения без LLM и контекстные.
- [ ] UI: «осталось запросов сегодня» из `quota_usage`. Квота 0 → только без LLM.

**Готово когда:** сессия из сгенерированных упражнений проходится, битый JSON не
роняет сессию, счётчик квоты корректен.

## Этап 5. Мультиустройство (онлайн)

Заход с телефона и ноутбука. В онлайне почти всё уже готово — сервер источник истины.
Отдельного большого этапа не требуется, только проверки.

- [ ] `client_id` на попытку + серверный дедуп — уже сделаны на этапе 3, проверить.
- [ ] Прогресс, квота, наборы читаются с сервера, локального кэша состояния нет.
- [ ] Проверка: параллельные ответы с двух устройств не задваивают счётчики.
- [ ] Мелочь: если сессия начата на одном устройстве — на другом видно её как активную
      (или просто игнорируем, edge-case).

**Готово когда:** можно свободно переключаться телефон ↔ ноутбук, прогресс и счётчик
квоты сходятся.

**Офлайн-прохождение — не в MVP**, вынесено в этап 8.

## Закрытые решения

- Слово ↔ темы — **many-to-many** (`word_folders`).
- Авторизация — **Telegram**, отдельный бот под приложение.
- Несколько устройств — **нужно**; онлайн-режим достаточно (офлайн — после MVP).
- Перевод — **MyMemory** (без ключа) + ручной ввод; Yandex Dictionary отклонён.
- Миграция из Me Words — **не делается**.
