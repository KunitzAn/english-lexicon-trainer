## Этап 4. Генерация контекстных упражнений (OpenRouter) ▶️

- [x] JSON-схема на типы `gap` (пропуск + банк слов) и `clickable` (абзац + выбор
      RU-перевода выделенного слова) + секция `glossary` (`_lib/gen-exercises.ts`).
- [x] Промпт (C1/C2, строгий JSON, `response_format: json_object`).
- [x] Клиент OpenRouter (`_lib/openrouter.ts`): явная цепочка из 3 `:free`-моделей
      (`minimax-m3` → `nemotron-3-super` → `gemma-4-26b`), фоллбек через `models:[...]`
      самого OpenRouter, таймаут 45 с, срезание `<think>`/```-заборов.
- [x] Батч: один запрос = набор упражнений на сессию (до 6).
- [x] Валидатор: `sense_id` из набора, тип из {gap,clickable}, ровно один `___`,
      целевое слово не светится в gap-тексте, `answer` ∈ bank/options, правильный
      RU-вариант = перевод из БД. Провал упражнения → выкидываем его; провал всего
      батча → `degraded`, фронт идёт на упражнения без LLM.
- [x] `exercises(user_id, type, payload jsonb, target_sense_ids, status, created_at)`,
      миграция 0004.
- [x] Запас: сгенерированное живёт как `reserve`, переиспользуется следующими
      сессиями; GC старше 7 дней. Фоновой пред-генерации нет (по кнопке «начать»).
- [x] `quota_usage(date PK, count)` — серверный счётчик, сброс по UTC-полуночи
      (03:00 МСК), лимит 50 (= дневной лимит `:free` OpenRouter). Единица
      возвращается (`refundQuota`) при недоступности модели; при 429 «дневной лимит»
      от OpenRouter квота обнуляется до конца суток UTC (`exhaustQuota`).

- [x] `generation_log(model, ok, error_kind, detail)` — `detail` хранит причину:
      тело ошибки OpenRouter, `finish_reason`, сырой content, список отбраковки по

- [x] Пройденные верно сгенерированные упражнения удаляются в `/api/attempts`.
- [x] Фронт: рендер `gap` и `clickable`; раннер чередует их с упражнениями без LLM

- [x] UI: «запросов к ИИ сегодня осталось N/50» на экране тренировки. Нет ключа /

- [x] Генерация 1:1 с набором (потолок 25) одним батч-запросом; короткие тексты

- [x] Формат тренировки на экране: `вперемешку` / `контекст` (только `gap`+`clickable`)

## Этап 5. Мультиустройство (онлайн) ▶️

Заход с телефона и ноутбука. Сервер уже источник истины (нет `localStorage` /
кэша состояния, `answered_at` ставит БД, `client_id` + пересчёт счётчиков из
`attempts` — идемпотентны). Одновременная работа под одним юзером с двух
устройств не рассматривается (гонки при параллельном сохранении и защита
конкурентного редактирования слов — **не делаем**).

**Что делаем:**

- [x] **Незаконченная сессия переживает перезагрузку и переезд на другое
      устройство.** Таблица `training_sessions(id, user_id UNIQUE, state jsonb,
      created_at, updated_at)` — одна активная на юзера (миграция 0006). `state` =
      собранный (перемешанный) список упражнений + позиция + буфер ответов
      (с готовыми `client_id`) + буфер разбора + формат. Эндпоинт
      `functions/api/sessions/index.ts`: `GET` (текущая или null; строку старше
      7 дней подчищает), `PUT` (upsert по `user_id` — старт новой молча заменяет
      старую), `DELETE`. `SessionView`: пустой `session` store при входе →
      `fetchServerSession()`; есть незаконченная → экран «продолжить» / «начать
      заново». `saveServerSession` (fire-and-forget, антидребезг) после каждого
      ответа; `clearServerSession` при успешном `POST /attempts` и при «начать
      заново». Баннер «незаконченная тренировка · N/M» на «Прогрессе» —
      «продолжить» / «сбросить». Смоук: 9/9 (local wrangler + Neon).
- [x] **Списки обновляются при возврате на вкладку** — composable
      `useRefreshOnFocus` (по `visibilitychange` / `focus`, антидребезг 4 с,
      игнор всплеска после монтирования). Подключён в «Темах», «Теме», «Всех
      словах» (тихий рефетч, если нет активного выделения) и на «Прогрессе»
      (статы + баннер).
- [ ] Ручная проверка: телефон ↔ ноут — прогресс, серия, квота сходятся;
      ответы не задваиваются; сессию можно продолжить на втором устройстве.

**Не делаем:** список активных сессий / «выйти со всех устройств» (при утере
устройства — смена `SESSION_SECRET` в Cloudflare разлогинивает разом).

**Офлайн-прохождение — не в MVP**, вынесено в этап 8.

## Этап 5.1. Выученность в списках слов + фильтр

Идея (зафиксирована, реализуем после этапа 5):

- **Показывать выученность прямо в плашке слова** — заливка слева направо
  примерно по проценту выученности. Способ заливки — **фон** (неяркая заливка
  части плашки), а не «ползущая» толстая рамка. Слева цветной акцент строки
  (уже есть), поверх — прогресс-заливка в тот же тон, но приглушённо.
- **Фильтр/сортировка списка**: новые / давно не трогали / самые невыученные /
  выученные. Кнопки-чипы над списком (как формат на «Тренировке»).
- Источник числа: пока нет финальной модели «выученности» (этап 6, шаг 5) —
  берём прокси `accuracy = correct/(correct+incorrect)` из `word_sense_progress`
  (0 попыток → «новое», показываем пустую плашку / метку). Агрегат по слову —
  среднее/минимум по его значениям. Когда модель зафиксируется — заменим число,
  визуал остаётся.
- Данные на клиент: расширить `GET /api/words` полями прогресса по каждому
  слову (или отдельный лёгкий `GET /api/words/progress`).

## Доработки из тестирования (бэклог)

Собрано по итогам ручного теста. Приоритет и порядок — отдельно; часть мелочи
можно закрыть попутно с этапом 6.

### Быстрые правки ✅

- [x] **Е/Ё как одна буква** при сравнении вариантов. `norm` вынесен в
      `lib/exercises.ts` и экспортируется: `normalize('NFC')` + `ё → е` +
      trim + lowercase; используется в `optIsCorrect`, `pickClass`, матче пар.
- [x] **Показывать перевод целевого слова после ответа** — для `gap` (выбор
      английского слова). В `choice` / `clickable` не показываем (там ответ —
      это и есть русский перевод). `flashcard` уже показывает при раскрытии.
- [x] **Серия дней — по локальной полуночи.** Клиент шлёт `?tz_offset=<мин>`
      (`-getTimezoneOffset()`) в `/api/stats`; сервер режет сутки
      `(answered_at at time zone 'UTC') + make_interval(mins => offset)` и так же
      считает «сегодня» в `computeStreak`. Смоук по SQL — ок.

### Средние

- [ ] **Иконки для папок.** Колонка `folders.icon`, выбор иконки в
      создании/переименовании темы, отрисовка в списке «Темы» и в шапке темы.
- [x] **После сохранения нового слова — назад в список, откуда пришли.**
      `AddWordView.save()` ведёт в `/folders/:id` (если добавляли в тему) или в
      `/words`, а не на карточку слова. Отдельный экран не нужен.
- [x] **EN-дистракторы из набора тренировки.** В `gap` банк вариантов
      пересобирается на клиенте (`gapBank` в `lib/exercises.ts`): правильный
      ответ + английские слова текущего набора (не встречающиеся в тексте),
      добор из банка модели, если слов в наборе мало.
- [ ] **Упражнение «мульти-пропуск».** Один текст с несколькими `___`, общий банк
      слов из набора — заполнить все пропуски. Новый тип + генерация + валидатор
      + рендер. Пересекается с «типы 3–5» этапа 4.

### Крупное

- [ ] **Шаринг папок между пользователями.** На папку — настройка видимости
      (`private` / доступна другим). Раздел «чужие папки»: смотреть публичные
      папки других юзеров, забирать себе отдельные слова (merge как при
      добавлении) или всю папку целиком (копия папки + слов в свой словарь).

### Модель «выученности» (продумать)

Сейчас порог не зафиксирован; `word_sense_progress` хранит только
`correct_count` / `incorrect_count` / `last_trained_at`. Чего хочется:

- **Не только счётчики, но и распределение по дням.** Важно, чтобы верные ответы
  были в **разные дни**, а не подряд в одной сессии. Черновая формула «выучено»:
  ≥ N различных дней с верным ответом (N≈2–3) И accuracy ≥ порога И, возможно,
  минимальный интервал между этими днями. Метрику «различных дней с верным
  ответом» можно считать из `attempts` без изменения схемы; либо
  денормализовать в `word_sense_progress` (`distinct_correct_days`, `learned_at`).
- **Ручная правка степени выученности через интерфейс.** Поле-override в
  `word_sense_progress` (напр. `mastery_override`: `new | learning | learned` или
  число 0..1), которое перебивает вычисленное значение. Сбрасывается кнопкой.
- **Настройка «что считать выученным» из интерфейса.** Пороги (N дней, min
  accuracy, интервал) — в пользовательские настройки (`settings jsonb` на `users`
  или таблица `app_config` ключ-значение). Пересекается с пунктом ниже.

- [ ] Порог «выучено» — зафиксировать формулу (с учётом «разные дни»).
- [ ] Настройки в конфиг-таблицу / env: веса формулы приоритета, доля новых,
      размер запаса, лимит сессии + пороги «выученности». Часть — редактируемые из UI.

**Готово когда:** приложением комфортно пользоваться ежедневно с телефона;
есть экран прогресса; понятно и настраиваемо, что считается выученным.
