# English Lexicon Trainer — пошаговый план разработки

> Рабочий план сборки. Основан на `PLAN.md`, но упорядочен под реализацию.
> Дата: 2026-08-28.
>
> **Принцип:** вертикальные срезы, деплой с первого этапа, приложение должно быть
> «проходимо руками с телефона» как можно раньше.

## Как пользоваться

- Этапы идут по порядку, внутри этапа — чек-лист.
- «Готово когда» — критерий закрытия этапа.
- Не начинать следующий этап, пока текущий не задеплоен и не проверен вручную на телефоне.

- ✅ **Этап 0** — каркас задеплоен, `vocab.kunitcan.online`, `/api/health` → `db_ok`.

В `PLAN.md`: генерация (этап 3) → упражнения (этап 4).

## Этап 3. Прогресс + подбор набора + упражнения без LLM ▶️

Здесь приложение впервые становится тренажёром — целиком без внешних API.

**Прогресс:**

- [x] `attempts(id, user_id, client_id UNIQUE, word_sense_id, exercise_id?,
      exercise_type, is_correct nullable, hint_used, answered_at)` — миграция 0003.
- [x] Запись попытки: пересчёт `word_sense_progress` из `attempts` (не инкремент),
      одним upsert. Идемпотентно по `client_id`.
- [x] Функция приоритета (`_lib/priority.ts`, формула `PLAN.md` §3),
      новые значения → `priority = 0.9`.

**Подбор набора:**

- [x] Ручной: папка + лимит, по порядку (`textNorm`, `position`).
- [x] Авто: топ по `priority`; доля новых значений ≤ ~40% (`NEW_SHARE`), при нехватке
      повторяемых — добор новыми.
- [x] `GET /api/training-set?mode=auto|manual&folder=&limit=` — отдаёт карточки
      + `distractor_pool` для дистракторов.

**Упражнения без LLM** (из `word_senses`, без внешних запросов):

- [x] Тип A: сопоставление пар EN↔RU тапами (`match`).
- [x] Тип B: флеш-карточка с самооценкой «знал / не знал» (`flashcard`).
- [x] Тип C: выбор перевода из вариантов (`choice`), дистракторы — соседние значения
      набора + общий пул.
- [x] Раннер сессии (`SessionView`): упражнение → тап-ответ → сравнение → буфер
      попыток → `POST /api/attempts` в конце → далее.
- [x] «Подсмотреть перевод» (choice) → `hint_used=true`, `is_correct=null`,
      счётчики не трогаются. Для `match` — «показать ответы» с тем же эффектом.
- [x] Экран разбора в конце сессии: слово, транскрипция, перевод, пример, ✓/✗/подсказка.
- [x] Итог сессии: верно / неверно / подсказок.

**Готово когда:** ✅ проверено на `vocab.kunitcan.online` — набор (авто и по теме),
сессия тапами (все 3 типа + «подсмотреть»), итог; неверная пара мигает красным
и гаснет, первая ошибка засчитывается неверной.

## Этап 4. Генерация контекстных упражнений (OpenRouter) ▶️

- [x] JSON-схема на типы `gap` (пропуск + банк слов) и `clickable` (абзац + выбор
      RU-перевода выделенного слова) + секция `glossary` (`_lib/gen-exercises.ts`).
- [x] Промпт (C1/C2, строгий JSON, `response_format: json_object`).
- [x] Клиент OpenRouter (`_lib/openrouter.ts`): явная цепочка из 3 `:free`-моделей
      (`minimax-m3` → `nemotron-3-super` → `gemma-4-26b`), фоллбек через `models:[...]`
      самого OpenRouter, таймаут 45 с, срезание `<think>`/```-заборов.
- [x] Батч: один запрос = набор упражнений на сессию (до 6).
- [x] Валидатор: `sense_id` из набора, тип из {gap,clickable}, ровно один `___`,
      целевое слово не светится в gap-тексте, `answer` ∈ bank/options, правильный
      RU-вариант = перевод из БД. Провал упражнения → выкидываем его; провал всего
      батча → `degraded`, фронт идёт на упражнения без LLM.
- [x] `exercises(user_id, type, payload jsonb, target_sense_ids, status, created_at)`,
      миграция 0004.
- [x] Запас: сгенерированное живёт как `reserve`, переиспользуется следующими
      сессиями; GC старше 7 дней. Фоновой пред-генерации нет (по кнопке «начать»).
- [x] `quota_usage(date PK, count)` — серверный счётчик, сброс по UTC, лимит 45.
      Единица возвращается (`refundQuota`), если запрос не дошёл до модели
      (HTTP-ошибка / таймаут / сеть). `GET /api/quota`.
- [x] `generation_log(model, ok, error_kind, detail)` — `detail` хранит причину:
      тело ошибки OpenRouter, `finish_reason`, сырой content, список отбраковки по
      упражнениям. Дублируется в `console.warn` Function и в ответ (`gen_detail`,
      фронт пишет в консоль браузера).
- [x] Пройденные верно сгенерированные упражнения удаляются в `/api/attempts`.
- [x] Фронт: рендер `gap` и `clickable`; раннер чередует их с упражнениями без LLM
      (контекстное вместо своего для того же значения).
- [x] UI: «запросов к ИИ сегодня осталось N/45» на экране тренировки. Нет ключа /
      квота 0 / битый ответ → только упражнения без LLM.
- [ ] Типы 3–5 (multiple-choice в контексте, сортировка по группам, верно/неверно) — позже.
- [ ] Ретрай генерации при soft-ошибке (`empty`/`bad_json`) — пока нет, экономим квоту.

**Готово когда:** ⏳ проверить на проде — добавить `OPENROUTER_API_KEY` в Pages как
Secret, пройти сессию со сгенерированными упражнениями; при недоступной модели
сессия не падает, счётчик квоты уменьшается. Локально (wrangler + Neon + реальный
OpenRouter) проверено: генерация, валидатор, запас/переиспользование, `degraded`,
удаление пройденных, запись `attempts.exercise_id`.

## Закрытые решения

- Слово ↔ темы — **many-to-many** (`word_folders`).
- Авторизация — **Telegram**, отдельный бот под приложение. Домен: `vocab.kunitcan.online`.
- Пользователи — **таблица `users`**, первый вход = владелец, дальше по приглашению (не env).
- Данные — **у каждого пользователя свои** (`user_id` во всех персональных таблицах).
  Общее: `translation_cache`, квота OpenRouter (`quota_usage`).
- Несколько устройств — **нужно**; онлайн-режим достаточно (офлайн — после MVP).
- Перевод — **MyMemory** (без ключа) + ручной ввод; Yandex Dictionary отклонён.
- Миграция из Me Words — **не делается**.
- Стек — Vue 3 + Vite, Cloudflare Pages + Pages Functions, Neon + Drizzle, npm.
- `part_of_speech` — убран из UI (колонка в БД осталась дремать). Вернём чипсами
  в этапе 4, если понадобится для качества генерации упражнений.
